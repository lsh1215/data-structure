왜 자료구조부터인가

인덱스를 타는지 안 타는지, 왜 LIKE '%x'는 느린지, 왜 Redis가 O(1)인지는 전부 내부 자료구조의 모양에서 결정됩니다. 튜닝 가이드를 외우는 대신 모양을 기억하세요.

직접 조작해서 확인

모든 시각화는 실제 알고리즘 구현 위에서 동작합니다. 값을 넣고, 지우고, 차수를 바꾸고, 속도를 조절하면 트리와 해시 테이블이 실제로 그렇게 변합니다.

숫자까지 같이

애니메이션 아래에는 항상 계측값이 붙습니다. 트리 높이, 비교 횟수, 디스크 I/O, load factor, BM25 점수 — 눈으로 본 것을 숫자로 다시 확인합니다.
